### 1. Dynamic Cast (Dinamikus típusmódosítás)
A `dynamic_cast` futási időben ellenőrzi, hogy egy ősosztályú mutató (vagy referencia) átalakítható-e egy adott gyerekosztály típusára.

*   **Feltétel**: Csak polimorf típusokon működik (az ősosztályban lennie kell legalább egy `virtual` metódusnak).
*   **Működése**: Ha az átalakítás sikeres, visszaadja az új típusú mutatót; ha sikertelen, `nullptr`-t ad vissza.
*   **Mire jó?** Biztonságos típusellenőrzésre, amikor egy heterogén kollekcióban (pl. ősosztályú mutatók tömbjében) keressük a specifikus gyerekosztályokat.

```cpp
Base* basePtr = new Derived();

// Próbáljuk meg Derived típusra alakítani
Derived* derivedPtr = dynamic_cast<Derived*>(basePtr);

if (derivedPtr != nullptr) {
    // Sikeres volt a kasztolás, használhatjuk a gyerekosztály metódusait
    derivedPtr->specialMethod();
} else {
    // A mutató nem Derived típusú objektumra mutatott
}
```

### 2. Kivételkezelés: Throw, Try - Catch
A program normál futását megakasztó hibák jelzésére és kezelésére szolgál.

*   **Throw**: A hiba jelzése. Bármilyen típus (int, string, objektum) "eldobható".
*   **Try**: Egy kódblokk, amelyben figyeljük a potenciális hibákat.
*   **Catch**: A hiba elkapása és lekezelése. A típusának egyeznie kell a dobott érték típusával.

```cpp
void functionThatMightFail(int value) {
    if (value == 0) {
        throw std::string("Hiba: Nulla ertek!"); // Hiba dobása
    }
}

int main() {
    try {
        functionThatMightFail(0); // Próbálkozás
    } catch (const std::string& error) {
        // Itt kezeljük le a hibát, így a program nem áll le hirtelen
        std::cerr << "Elkapott hiba: " << error << std::endl;
    }
}
```

### 3. Privát Constructor és Statikus metódus
Ez a technika megakadályozza az objektum közvetlen példányosítását, és egy kontrollált csatornán keresztül teszi azt lehetővé.

*   **Privát konstruktor**: Kívülről nem hívható meg a `new` vagy a sima deklaráció.
*   **Statikus metódus**: Az osztályhoz tartozik, nem egy példányhoz. Meghívható anélkül is, hogy már létezne az objektum. Ez a metódus "belülről" látja a privát konstruktort, így le tudja gyártani a példányt.
*   **Mire jó?** Validációra (csak akkor hozunk létre objektumot, ha a bemeneti adatok jók) vagy speciális tervezési mintákhoz (pl. Singleton).

```cpp
class MyClass {
private:
    MyClass() {} // Kívülről nem lehet példányosítani

public:
    static MyClass* createInstance(bool condition) {
        if (condition) {
            return new MyClass(); // Belülről elérhető a konstruktor
        }
        return nullptr; // Ha a feltétel nem teljesül, nem hozunk létre semmit
    }
};

// Használata:
MyClass* obj = MyClass::createInstance(true);
```

### 4. Prefix és Suffix ++ Operátorok implementációja
Az inkrementáló operátorok túltöltésekor meg kell különböztetni a két irányt.

*   **Prefix (`++obj`)**: Növeli az értéket, majd visszatér a módosított objektummal. Gyorsabb, mert nem készül másolat.
*   **Suffix (`obj++`)**: Elmenti a jelenlegi állapotot egy másolatba, növeli az eredeti objektumot, de a **módosítás előtti** másolattal tér vissza.
*   **Megkülönböztetés**: A suffix operátor egy "látszat" `int` paramétert kap a szignatúrában.

```cpp
class Counter {
    int value;
public:
    Counter(int v) : value(v) {}

    // Prefix: ++c
    Counter& operator++() {
        value++;
        return *this; // Módosított önmagával tér vissza
    }

    // Suffix: c++
    Counter operator++(int) {
        Counter temp = *this; // Régi állapot elmentése
        value++;              // Eredeti növelése
        return temp;          // A régi állapotot adjuk vissza
    }
};
```

### 5. Stream beszúró operátor

A `<<` operátor (stream beszúró operátor) túltöltésével érhetjük el, hogy egy saját osztály objektumát közvetlenül kiírathassuk a képernyőre (pl. `std::cout << obj;`).

A megvalósításnak két fő szabálya van:

1. **Globális függvényként** kell megírni (nem lehet az osztály sima tagfüggvénye, mert a bal oldali operandus nem az objektumunk, hanem az `std::ostream`).
2. Az osztályon belül **`friend`** (barát) kulcsszóval kell deklarálni, hogy hozzáférjen a privát adattagokhoz.

### Általános példa

```cpp
#include <iostream>

class MyClass {
private:
    int x;
    int y;

public:
    MyClass(int x, int y) : x(x), y(y) {}

    // A friend deklaráció az osztályon belül (bárhol állhat, akár a private-ban is)
    friend std::ostream& operator<<(std::ostream& os, const MyClass& obj);
};

// Az operátor tényleges kifejtése az osztályon kívül
std::ostream& operator<<(std::ostream& os, const MyClass& obj) {
    os << "(" << obj.x << ", " << obj.y << ")"; // Formázott kiíratás
    return os; // Visszatérünk a folyammal, hogy láncolható legyen (pl. cout << a << b;)
}

int main() {
    MyClass obj(5, 10);
    
    // Így közvetlenül használható cout-tal:
    std::cout << "Az objektumom: " << obj << std::endl;
    
    return 0;
}

```

### Miért pont így néz ki a szignatúra?

* **`std::ostream& os`**: Ez a bal oldali operandus (maga a `std::cout`). Referenciaként vesszük át, mert a stream nem másolható.
* **`const MyClass& obj`**: Ez a jobb oldali operandus (amit kiírunk). Konstans referencia, hogy ne másoljuk feleslegesen az objektumot, és garantáljuk, hogy a kiíratás nem módosítja azt.
* **`std::ostream&` (visszatérési érték)**: Magát az `os` folyamot adjuk vissza referenciaként, ez teszi lehetővé a `std::cout << a << b << c;` jellegű láncolást.


### 6. Forward declaration

```cpp
#include <iostream>

// 1. ELŐZETES DEKLARÁCIÓ (Forward Declaration)
// Megmondjuk a fordítónak, hogy lesz egy 'B' nevű osztály, így már használható referenciaként.
class B; 

// 2. AZ ELSŐ OSZTÁLY DEFINÍCIÓJA
class A {
public:
    // Mivel a 'B'-t már deklaráltuk, a referenciáját (&) elfogadja a fordító
    void bemutatkozik(const B& b); 
};

// 3. A MÁSODIK OSZTÁLY TELJES DEFINÍCIÓJA
// Itt már a fordító mindent lát, amit a 'B'-ről tudni kell.
class B {
public:
    void uzenet() const {
        std::cout << "Szia, en a B osztaly vagyok!" << std::endl;
    }
};

// 4. AZ ELSŐ OSZTÁLY METÓDUSÁNAK KIFEJTÉSE
// Ezen a ponton a fordító már ismeri a 'B' osztály belső tagjait is (pl. az uzenet() metódust), 
// így végre megírhatjuk a függvény törzsét.
void A::bemutatkozik(const B& b) {
    b.uzenet(); 
}

int main() {
    A a_objektum;
    B b_objektum;
    
    a_objektum.bemutatkozik(b_objektum);
    return 0;
}
```

### Miért pont ez a sorrend?
* Ha az ***A::bemutatkozik*** függvényt egyből az A osztályon belül akarnád megírni (inline), a fordító hibát dobna, mert a ***b.uzenet()*** sor olvasásakor még fogalma sem lenne róla, hogy a B osztálynak van-e egyáltalán ***uzenet()*** nevű függvénye.

* Az előzetes deklaráció csak azt engedi meg, hogy mutatót (B*) vagy referenciát (B&) hozzunk létre, de a típus belsejébe csak akkor láthat be a fordító, ha a teljes osztálydefiníció (a 3. lépés) már megtörtént.
