### 1. Dynamic Cast (Dinamikus típusmódosítás)
A `dynamic_cast` futási időben ellenőrzi, hogy egy ősosztályú mutató (vagy referencia) átalakítható-e egy adott gyerekosztály típusára.

*   **Feltétel**: Csak polimorf típusokon működik (az ősosztályban lennie kell legalább egy `virtual` metódusnak).
*   **Működése**: Ha az átalakítás sikeres, visszaadja az új típusú mutatót; ha sikertelen, `nullptr`-t ad vissza.
*   **Mire jó?** Biztonságos típusellenőrzésre, amikor egy heterogén kollekcióban (pl. ősosztályú mutatók tömbjében) keressük a specifikus gyerekosztályokat.

```cpp
Base* basePtr = new Derived();

// Próbáljuk meg Derived típusra alakítani
Derived* derivedPtr = dynamic_cast<Derived*>(basePtr);

if (derivedPtr != nullptr) {
    // Sikeres volt a kasztolás, használhatjuk a gyerekosztály metódusait
    derivedPtr->specialMethod();
} else {
    // A mutató nem Derived típusú objektumra mutatott
}
```

### 2. Kivételkezelés: Throw, Try - Catch
A program normál futását megakasztó hibák jelzésére és kezelésére szolgál.

*   **Throw**: A hiba jelzése. Bármilyen típus (int, string, objektum) "eldobható".
*   **Try**: Egy kódblokk, amelyben figyeljük a potenciális hibákat.
*   **Catch**: A hiba elkapása és lekezelése. A típusának egyeznie kell a dobott érték típusával.

```cpp
void functionThatMightFail(int value) {
    if (value == 0) {
        throw std::string("Hiba: Nulla ertek!"); // Hiba dobása
    }
}

int main() {
    try {
        functionThatMightFail(0); // Próbálkozás
    } catch (const std::string& error) {
        // Itt kezeljük le a hibát, így a program nem áll le hirtelen
        std::cerr << "Elkapott hiba: " << error << std::endl;
    }
}
```

### 3. Privát Constructor és Statikus metódus
Ez a technika megakadályozza az objektum közvetlen példányosítását, és egy kontrollált csatornán keresztül teszi azt lehetővé.

*   **Privát konstruktor**: Kívülről nem hívható meg a `new` vagy a sima deklaráció.
*   **Statikus metódus**: Az osztályhoz tartozik, nem egy példányhoz. Meghívható anélkül is, hogy már létezne az objektum. Ez a metódus "belülről" látja a privát konstruktort, így le tudja gyártani a példányt.
*   **Mire jó?** Validációra (csak akkor hozunk létre objektumot, ha a bemeneti adatok jók) vagy speciális tervezési mintákhoz (pl. Singleton).

```cpp
class MyClass {
private:
    MyClass() {} // Kívülről nem lehet példányosítani

public:
    static MyClass* createInstance(bool condition) {
        if (condition) {
            return new MyClass(); // Belülről elérhető a konstruktor
        }
        return nullptr; // Ha a feltétel nem teljesül, nem hozunk létre semmit
    }
};

// Használata:
MyClass* obj = MyClass::createInstance(true);
```

### 4. Prefix és Suffix ++ Operátorok implementációja
Az inkrementáló operátorok túltöltésekor meg kell különböztetni a két irányt.

*   **Prefix (`++obj`)**: Növeli az értéket, majd visszatér a módosított objektummal. Gyorsabb, mert nem készül másolat.
*   **Suffix (`obj++`)**: Elmenti a jelenlegi állapotot egy másolatba, növeli az eredeti objektumot, de a **módosítás előtti** másolattal tér vissza.
*   **Megkülönböztetés**: A suffix operátor egy "látszat" `int` paramétert kap a szignatúrában.

```cpp
class Counter {
    int value;
public:
    Counter(int v) : value(v) {}

    // Prefix: ++c
    Counter& operator++() {
        value++;
        return *this; // Módosított önmagával tér vissza
    }

    // Suffix: c++
    Counter operator++(int) {
        Counter temp = *this; // Régi állapot elmentése
        value++;              // Eredeti növelése
        return temp;          // A régi állapotot adjuk vissza
    }
};
```
